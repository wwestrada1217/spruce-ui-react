## Property / behavior / event / accessibility matrix

| Surface | Angular property or behavior | React API and implementation | Events / callbacks | Accessibility, i18n, RTL, theme |
| --- | --- | --- | --- | --- |
| `ColorPicker` | Preset `colors`, selected `value`, trigger `label` and `icon`, custom native color input, active swatch, open/close/toggle methods | `ColorPickerColor`, controlled `value`/`onChange`, `colors`, `label`, `icon`, controlled `open`/`onOpenChange`, `disabled`, `readOnly`, shared field state props; `ColorPickerHandle` methods | `onChange(value)`, `onOpenChange(open)`; handle `openPanel`, `close`, `toggle` | Portaled `Popover`; trigger is a named button with `aria-expanded`/`aria-haspopup`; preset grid is a labelled listbox with selected options and arrow/Home/End/Enter/Escape support; labels use `useI18n`; logical direction and tokenized light/dark CSS |
| `EmojiPicker` | Preset/custom `emojis`, selected `value`, trigger icon-or-value, search by label/keywords, selected object output, focus search after open | `EmojiPickerEmoji`, controlled `value`/`onChange`, `onSelected`, `emojis`, `label`, `icon`, controlled `open`/`onOpenChange`, `disabled`, `readOnly`; `EmojiPickerHandle` methods | `onChange(value)`, `onSelected(emoji)`, `onOpenChange(open)`; handle `openPanel`, `close`, `toggle` | Portaled labelled dialog; search is a labelled native search input; options use listbox/option selected state, keyboard navigation, focus restoration, localized search/no-results labels, RTL direction, design tokens |
| `FormBuilder` schema | `schema` / `schemaChange`, sections, fields, tabs, options, columns, defaults, design and preview modes | `FormBuilderSchema`, `FormBuilderField`, `FormBuilderOption`, `FormBuilderGridColumn`, `FormBuilderSection`, `FormBuilderTab`, `FormBuilderFieldType`, controlled `schema`/`onSchemaChange`, `value`/`onValueChange`, `mode`/`onModeChange` | `onSubmit(FormBuilderSubmitEvent)`; all field edits emit a new controlled schema/value; toolbar content maps to `toolbar` children | Toolbar, palette, section, property panel, tabs, grid, and preview use semantic regions, labels, focus-visible controls, logical CSS, localized chrome, and theme tokens |
| `FormBuilder` design behavior | Add/remove/move/rename sections; add/remove/duplicate fields; field property editing; tabs; grid placement; drag/drop and resize; read-only design state | Same operations are exposed through `FormBuilderHandle` and rendered through native drag/drop plus pointer/keyboard resize; `readOnly`, `showToolbar`, `showPalette`, `showProperties` control the surface | Handle methods are imperative equivalents for Angular public methods; controlled callbacks remain the source of truth | Design cards are keyboard selectable; resize handle supports arrow/Home/End; destructive buttons are named; design-only controls are omitted when read-only |
| `FormBuilder` preview | Built-in controls for text/email/number/password/tel/url/textarea/select/checkbox/switch/date/daterange/radio/masked/combobox/grid-combobox/datagrid; required/min/max/length/email/URL validation | Preview composes existing Spruce `Field`, `Input`, `Textarea`, `Select`, `Checkbox`, `Switch`, `DatePicker`, `DateRangePicker`, `RadioGroup`, `MaskedInput`, `Combobox`, and `GridCombobox`; datagrid fields use a controlled tokenized table editor | `onValueChange` receives a new record; `onSubmit` carries `value`, `valid`, and `errors`; field controls preserve value-not-event callbacks | Field owns labels, hints, errors, `aria-invalid`, `aria-required`, and alert feedback; controls inherit i18n/RTL/theme behavior from existing primitives |
| `FormBuilder` persistence | `save()` deep snapshot, `restore(schema)`, `resetValues()`, `submit()` | `FormBuilderHandle` with `save`, `restore`, `resetValues`, `submit` | `submit()` calls `onSubmit` with a copied payload; `restore` and reset emit controlled changes | No storage or DI is introduced; persistence remains consumer-owned |
| Data context adapter | Bridges form model to a selected record; dirty/valid/loading/state/navigation helpers; submit updates current or adds a record; optional save | `FormBuilderDataContextAdapter<T>` and `createFormBuilderDataContextAdapter`; `useFormBuilderDataContextAdapter` subscribes through existing React `DataContext` / `FormModel` contracts | `onSubmit` returns `Promise<void>`; `setValue`, `addNew`, `deleteCurrent`, `discardChanges`, `next`, `previous`, `first`, `last`, `getChangeSummary` | Uses framework-neutral React data APIs; no Angular signals, injection, observables, or directives are copied |
| Lookup patterns | `IDataSource`/URL/local arrays, display/value fields, search fields, server paging, virtual scroll, selected raw record, row templates | Existing `LookupSource`, `readLookupPage`, `displayField`, `valueField`, `searchFields`, `pageSize`, `virtualScroll`, `virtualPaging`, `renderOption`/`renderRow`, `onSelectedItem` were inspected and retained; new docs show idiomatic React state/callback usage | Controlled `onChange` plus selected-object `onSelectedItem` | Existing listbox/combobox keyboard model, portaled placement/dismissal, `useI18n`, logical direction, and tokenized dark/light CSS are reused; Angular `IDataSource` maps to `IReadableDataSource` or a URL/local source |

Angular-only mechanisms intentionally not copied: signal models, `FormValueControl`, dependency injection, `NgTemplateOutlet`, Angular content-projection selectors, and `Observable` return values. React children, render callbacks, controlled props, imperative handles, and the existing data-context hooks provide the same user-visible contract.
