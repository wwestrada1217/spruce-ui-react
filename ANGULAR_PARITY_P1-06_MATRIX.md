# P1.0-06 notification and feedback parity matrix

Baseline read from Angular `projects/spruce-ui/core` (`alert.ts`, `progress-bar.ts`, `spinner.ts`, `circular-progress.ts`), Angular `projects/spruce-ui/overlays` (`toast.ts`, `snackbar.ts`, `notification-center.ts`), the Angular component documentation pages for all seven surfaces, and the Angular decorative-background motif API used by Alert and NotificationCenter. React counterparts were inspected in `src/components/alert`, `progress-bar`, `spinner`, `toast`, and `snackbar`.

Angular `input`, `output`, `model`, signals, injectable services, and content projection map to React props, callbacks, context hooks, local state, and `children`. The React API remains controlled where a value can be changed by the user or component chrome.

## Shared parity decisions

- `useI18n()` supplies localized labels, interpolation, number formatting, and the active direction; no Angular service or dependency injection is copied.
- Decorative motifs are ornamental only: they are absolutely positioned inside an isolated stacking context, clipped, pointer-transparent, and `aria-hidden`. Physical named anchors such as `center-right` stay physical in RTL; layout spacing and flow use logical CSS properties.
- All new CSS uses Spruce semantic, spacing, radius, motion, and focus tokens with fallbacks only for resilience. Animations stop under `prefers-reduced-motion`; motif art is hidden under forced colors.
- Service-backed Angular notifications use React context hooks because that is the idiomatic application boundary; render state and public callbacks remain React-controlled rather than signal-backed.
